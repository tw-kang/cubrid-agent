# CONTEXT.md — glossary

Canonical terms for this repo. Keep entries implementation-free.

| Term | Meaning |
|---|---|
| **Skill** | A self-contained agent capability directory (`SKILL.md` + optional `scripts/`, `references/`, `examples/`), distributed via the `vercel-labs/skills` CLI. |
| **`jira` skill** | The auxiliary skill in this repo that fetches CUBRID Jira issue context. Not to be confused with the upstream projects below. |
| **cubrid-jira** | vimkim's external CLI project (github.com/vimkim/cubrid-jira): cache-first reads, JQL search, dry-run-default writes against jira.cubrid.org. Upstream source for vendored functionality; never a runtime dependency of skills (see ADR 0001). |
| **cubrid-jira-fetcher** | The older upstream fetch-only project, since absorbed into cubrid-jira. Historical credit lines may still reference it. |
| **Vendoring** | Copying (and adapting to stdlib-only) the needed portion of an external project's source into a skill's `scripts/`, with upstream credit — instead of requiring the user to install the external project. |
| **Consumer skill** | A skill that auto-invokes the `jira` skill when a CBRD-XXXXX token appears in the request (all `cubrid-*-tc-*`, review, and fail-reasoning skills). |
| **CBRD-XXXXX** | A CUBRID Jira issue key. Filenames lowercase it as `cbrd_xxxxx`. |

## CTP shell-testcase terms

Vocabulary for the `cubrid-shell-tc-create` skill (see also `cubrid-shell-tc-create/docs/adr/`).

| Term | Meaning |
|---|---|
| **CTP** | CUBRID Test Program — the runner that executes shell testcases and collects pass/fail results. |
| **init_path / init.sh** | Env var pointing at CTP's `shell/init_path`; `init.sh` is sourced to load every helper function. |
| **Entry script** | The `{name}/cases/{name}.sh` that owns one full test lifecycle (init → setup → test → verify → cleanup). |
| **Helper script** | A script in the same `cases/` dir called by the entry script; owns no lifecycle of its own. |
| **`write_ok` / `write_nok`** | CTP calls recording pass / fail for a case (`write_nok` may attach evidence); every code path must reach exactly one. |
| **`finish`** | Mandatory final call: stops services, reverts all conf changes, releases broker shared memory. |
| **Answer file** | Expected-output baseline generated by CTP's `init answer` mode — produced by running, never hand-written. |
| **broker1** | The default CUBRID broker name in testcases (not `query_editor`); its port and CAS process name derive from it. |
| **CAS** | Common Application Server — a broker worker process (`broker1_cub_cas`) that handles client connections. |
| **single-CAS** | Forcing `MIN/MAX_NUM_APPL_SERVER=1` so one deterministic CAS handles every request (needed for crash / reuse repros). |
| **Coredump verify** | A pass criterion asserting no new `core.*` / `*coredump*` appears (baseline count before vs. after the action). |
| **`xgcc`** | An init.sh wrapper that compiles CCI C clients with `$CUBRID` include/lib, `-lcascci`, and bit/OS detection — used over raw `gcc`. |
| **test-shell pod** | A k8s pod holding a CUBRID build where CTP runs a testcase for real — the preferred verification environment. |
