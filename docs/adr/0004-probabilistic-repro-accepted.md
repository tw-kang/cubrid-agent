# 확률적으로만 재현되는 버그도 TC 대상으로 한다 — 기준은 "fix 후 결정성"

"SQL 재현성"을 "단일 실행으로 회귀를 검출할 수 있어야 한다"로 정의하면 현재 대상 풀(QA Scenario Required 7건)에서 적격 이슈가 0건이다. 실제 걸림돌은 CBRD-26799/26797 같은 race 버그의 재현율(~6%/회)뿐이었다. CI가 실제로 요구하는 것은 **fix 후 빌드에서 `.answer`가 매회 일치하는 것**(테스트가 CI를 흔들지 않는 것)이고, **재발 검출력**(fix 전 빌드에서 실패할 확률)은 별개 속성이다. 따라서 적격 기준을 전자로 정의하고, 후자는 리뷰의 평가 항목으로 분리한다 — Author는 반복 rebuild 등으로 검출력 증폭을 시도하고, 한계는 PR Remarks에 명시한다. "재발을 가끔만 잡는 테스트라도 없는 것보다 낫다"는 판단이며, 실제로 기존 SQL TC들이 이 버그로 flaky fail하며 버그를 드러낸 전례가 근거다.

## Considered Options

- 엄격 기준(단일 실행 결정적 검출) 유지 + Select 필터 확장으로 순수 SQL 버그 탐색 — 풀 확장 범위가 또 다른 협의 대상이 되고, PoC가 무기한 지연.
- 엄격 기준 유지 + 대상 없으면 "대상 없음" 종료 — 봇의 정상 동작이지만 PoC의 파이프라인 실증 목적을 달성하지 못함.
